# Deploying Parakh

Parakh has two parts that deploy **separately**:

| Part | What it is | Where it goes |
|---|---|---|
| `frontend/` | Static HTML/CSS/JS | **Netlify** |
| `backend/`  | FastAPI + Tesseract OCR + SQLite | **Render** (or Railway / Fly.io) |

Netlify cannot run the backend — it only serves static files and small
serverless functions, and the backend needs a persistent process, a system
binary (Tesseract), and disk for the database. So: backend first, then point
the frontend at it.

---

## 1. Deploy the backend (Render)

Render's free tier can build straight from the included `Dockerfile`, which
installs Tesseract for you.

1. Push this repo to GitHub (see the `.gitignore` note below first).
2. On [render.com](https://render.com) → **New +** → **Web Service** → connect
   your repo.
3. Set:
   - **Root Directory**: `backend`
   - **Environment**: `Docker` (Render auto-detects the `Dockerfile`)
   - **Instance Type**: Free is fine for a demo
4. Add environment variables (Render dashboard → Environment):
   - `LM_SECRET_KEY` = any long random string (used to sign login tokens)
   - `LM_ALLOWED_ORIGINS` = your Netlify URL once you have it, e.g.
     `https://parakh-demo.netlify.app` (comma-separate multiple origins;
     defaults to `*` if unset, which is fine to start with)
5. Deploy. When it's live you'll get a URL like
   `https://parakh-backend.onrender.com`. Check it:
   ```
   curl https://parakh-backend.onrender.com/api/health
   ```
   should return `{"status":"ok", ...}`.

**Demo accounts** (auto-seeded on first boot): `inspector1` / `inspect123`,
`admin` / `admin123`.

**Note on free-tier disk:** Render's free web services don't have a
persistent disk attached by default, so the SQLite database resets on every
redeploy (the app reseeds demo data automatically on startup, so it always
comes back up in a working state — you just won't keep manually-added scan
history across redeploys). Fine for a hackathon demo; if you need real
persistence later, attach a Render Disk or move to Postgres.

---

## 2. Point the frontend at the backend

Open `frontend/js/config.js` and set it to your Render URL:

```js
window.LM_API_BASE = "https://parakh-backend.onrender.com";
```

Commit that change before deploying the frontend.

---

## 3. Deploy the frontend (Netlify)

**Option A — drag and drop (fastest, no Git needed):**
1. Go to [app.netlify.com/drop](https://app.netlify.com/drop)
2. Drag your local `frontend/` folder onto the page
3. Done — you get a live URL immediately

**Option B — connect Git (recommended for updates later):**
1. Push the repo to GitHub
2. Netlify → **Add new site** → **Import an existing project** → pick the repo
3. The included `netlify.toml` already sets the base directory to `frontend`
   and publish directory to `.` — Netlify will pick this up automatically,
   no build command needed since there's no bundler.
4. Deploy.

---

## 4. Close the loop on CORS

Once you have your real Netlify URL, go back to Render → Environment →
set `LM_ALLOWED_ORIGINS` to that exact URL (e.g.
`https://parakh-demo.netlify.app`) and redeploy the backend. This locks the
API down to your frontend instead of accepting requests from `*`.

---

## Before pushing to GitHub

This project's `.gitignore` already excludes `venv/`, `__pycache__/`,
`compliance.db`, and `backend/uploads/` — none of those should ever be
committed (the venv alone is ~300MB and is regenerated by `pip install`
from `requirements.txt`; the database and uploads are runtime data, not
source). If you're starting from a zip that already had these committed,
run `git rm -r --cached backend/venv backend/__pycache__ backend/compliance.db backend/uploads`
once before your first push.

## Local development (unchanged)

```bash
cd backend
python -m venv venv && source venv/bin/activate   # or venv\Scripts\activate on Windows
pip install -r requirements.txt
# Tesseract must also be installed as a system binary:
#   Ubuntu/Debian: sudo apt install tesseract-ocr
#   macOS:         brew install tesseract
#   Windows:       https://github.com/UB-Mannheim/tesseract/wiki
uvicorn main:app --reload
```

Then open `frontend/index.html` with a local static server (e.g.
`python -m http.server` from inside `frontend/`) with
`frontend/js/config.js` left at `http://localhost:8000`.
